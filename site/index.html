赛题通 SaiTong
解决什么 功能 技术架构 开发过程 怎么验证 怎么用

一句话讲完：
把 60 篇赛题文档变成能问、能查、能追进度的一个页面。

面向 2026 OceanBase 数据库大赛参赛队伍的资料检索 + 进度跟踪单页应用。 语雀文档灌进 seekdb 做混合检索，队伍状态存进 PowerContext 做长期记忆， 每条答案都附原文链接；不配置任何 LLM Key 也能完整跑起来。

  • seekdb 混合检索
  • PowerContext 记忆
  • FastAPI
  • 无构建前端
  • 单容器部署

代码仓库 在线体验（部署中）

解决的问题

资料散在语雀约 60 篇文档里

赛题、算分规则、提交材料、各企业赛道说明分别成篇， 一个「这个题要交什么」要翻四五个页面，还说不清依据是哪一份文档写的。

→ 一次提问跨文档拿答案，答案下每条来源都能点开核对到原文段落。

队伍进度无处记

勾了哪些题、做到哪一步、卡在哪儿，通常散在群聊和各自的备忘里； 换个人接手、或者过两天回头看，就对不上状态了。

→ 每支队伍一份档案，选题 / 进度 / 卡点写进 PowerContext，服务重启后还在。

「下一步该做什么」要自己拼

截止时间、每道未完成的题要交的材料，得反复翻文档确认，容易漏。

→ 下一步页按未完成赛题从文档里抽待办，附倒计时与出处。

核心功能

技术架构：两个引擎各干各自擅长的事

seekdb 负责「资料」

  • 嵌入式：索引就是本地一个目录，没有独立服务要维护，容器里一起走。
  • 全文 + 向量混合检索：一次 hybrid_search 由服务端做 RRF 融合；中文分词用 jieba 加领域词典构造检索词，「提交材料」不会被切成「提交」「材料」。
  • 按赛道过滤：块上带 track 元数据，问 MiniMax 就不要把 AMD 的文档顶上来。
  • 弱向量兜底：一个查询词都不含的纯向量命中会被丢掉（日志字段 dropped_no_overlap）——宁可回「文档里没写」，也不给看着像的来源。
  • 检索日志：query、构造出的检索词、过滤条件、命中 id、耗时，每次一行。
  • 切块按文档的二级/三级标题走，块首拼「文档标题 / 章节」面包屑；代码围栏里的 # 不会被当成标题切碎。

PowerContext 负责「记忆」

  • 每队一个 scope：队名幂等创建（idempotency_key=team:<队名>），重复建档拿到同一个 scope。
  • 四类记忆：track-choice 选题、progress 进度、blocker 卡点、note 备注。
  • 旧进度置 forgotten：写新状态前把上一条评论区的旧记录 lifecycle 改成 forgotten，读回来只有一条有效，历史值不会冒充现状。
  • 重启可读回：数据在 POWERCONTEXT_HOME 磁盘上，杀掉服务再起，scope_id 与档案内容不变（这一条有真实子进程的单测）。
  • 调用日志：方法、路径、请求摘要、状态码、耗时，只记摘要不记全文。

数据流

  1. 语雀文档公开知识库 → scripts/fetch_docs.py 抓成带 front matter 的 Markdown 快照
  2. 切块按标题切、加面包屑、推断赛道、算内容哈希
  3. seekdb增量 upsert；查询走 hybrid_search + 赛道过滤
  4. 命中片段带 doc 标题 / 章节 / 原文链接 / 块 id
  5. 答案LLM 生成（带 [n] 引用）或抽取式兜底
  6. PowerContext并行：队伍选题 / 进度 / 卡点 → 问答与待办用它限定赛道
  7. 日志seekdb / powercontext / llm 三份 JSONL → 统计页与验收脚本读它

用 Qoder 开发的四个阶段

本项目通过 Qoder CLI 开发，提示词由 Claude 协助编写。 下面每个阶段都写了「实际发现的问题」——完整记录见仓库里的 docs/QODER_DEV_LOG.md。

1M0–M1 · 设计 + seekdb 知识库

先跑环境实测再写设计（默认 embedding 是 86MB 的 ONNX 英文模型、嵌入式 client 传 database= 会报错、同一目录可被两个进程读写），结论直接决定取舍。

  • 语雀卡片占位块抢第一名：卡片转出来的块正文几乎是空壳却排到 Top-1 → 清洗阶段丢弃卡片占位与空块，两条单测锁住。
  • 代码围栏里的 # 注释被当标题，切出碎块 → 只认围栏外的 H2/H3。
  • 默认向量模型中文区分度差（相似 0.335 vs 无关 0.306）→ 排序主要靠全文腿 + 服务端 RRF，这条限制原文写进 README，不藏。

2M2–M3 · PowerContext 档案 + 问答

先真机打一遍 PowerContext 再写客户端，字段名（scope_id / kind / state / 分页游标）是从实际响应里抄的，不是猜的。

  • 反复改状态后档案堆历史值 → 旧 progress 置 forgotten，接口断言只剩一条有效记录。
  • PowerContext 挂了不能连知识库一起 500 → 档案类接口 503，检索照常，健康检查里分开报状态。

3M4–M8 · 前端 / 部署 / 验收

无构建的原生 JS 单页 + 单容器 Docker + 一条命令的端到端验收脚本（24 项，--restart 25 项）。

  • 待办赛道串味：MiniMax 赛题的待办引用了 AMD 的文档 → 检索按该赛题所属赛道限定，先写失败测试再修。
  • 前端直接 innerHTML 会有 XSS → 所有插值过转义、链接只允许 http(s)，挡住 javascript:。
  • 验收断言自己写错过（把赛道名列表当成赛题清单比）→ 判据要能被反例打穿。

4M9–M10 · 语料同步 + 答案质量

把语料变成「可脚本再生」，并且不再随仓库分发；顺带修抽取式答案里的表格噪声。

  • 远端验收对中文队名抛 UnicodeEncodeError：进程内 TestClient 会自动做 IRI 编码所以本地全绿照不出来 → 编码放在传输层单点，5 条单测覆盖 URL 构造。
  • --restart 原来是假阳性：new 了一个新的服务对象，什么都没重启 → 改成重启应用自己持有的子进程，远端实例明确记 SKIP。
  • 「清洗」抓回来的正文反而改坏两篇：把字面 \n 还原、剥 <card>，动到了代码里的字面量 → 实测确认后删掉整个清洗函数，只留 strip()。
  • 抽取式答案混进 | :--- | :--- | 和残缺的 ** → 分隔行丢掉、表格行摊成「材料：要求」、落单的加粗符号去掉，5 条单测。

怎么验证它没在骗你

99个单元测试，全部离线可跑
python -m pytest tests -q
25/25项端到端验收通过
python scripts/verify.py --restart
约 430个检索块，来自约 60 篇语雀文档
数字随文档更新略有变化

验收步骤摘要（仓库 samples/VERIFY.md 里有完整实测输出）：

  1. 抓语料：scripts/fetch_docs.py 从公开页面生成 Markdown 快照 + 清单（语料不随仓库分发，目录空着时导入脚本与容器入口会自动先抓一次）。
  2. 导入：scripts/ingest.py 切块写进 seekdb，按内容哈希增量更新，打印块数与赛道分布。
  3. 起服务：bash scripts/start.sh（自动拉起 PowerContext 子进程），打开 http://127.0.0.1:7860。
  4. 跑验收：scripts/verify.py 逐项打印 PASS/FAIL 与实际字段——页面、健康、赛道、检索、建档、选题、进度、卡点、复读、问答、待办、统计、三份日志；--restart 多验一项「重启 PowerContext 后档案仍在」。
  5. 部署后复跑：同一个脚本 --base-url http://<host>:7860 对已部署实例验一遍，判据与本机同一口径。

尚未实跑的也照写着：浏览器内的页面交互（开发机没有浏览器，只有 API 契约与静态资源可达的自动核对）、 魔搭创空间侧的构建（没有 docker daemon）。

怎么用起来

本地跑

python -m pip install -r requirements.txt
python scripts/ingest.py          # 语料为空会自动抓语雀
bash scripts/start.sh             # http://127.0.0.1:7860

PowerContext 由应用自己拉起，端口、数据目录都走环境变量，默认值即可。

容器跑

docker build -t saitong .
docker run -d -p 7860:7860 \
  -v "$PWD/docker-runtime:/app/.runtime" saitong

挂卷是必需的：seekdb 索引和队伍档案都在容器内 $DATA_DIR，不挂则实例回收后档案丢失。

  • 代码仓库：github.com/timbermanQAQ/saitong
  • 在线体验：modelscope.cn/studios/Timberman/saitong（魔搭创空间 Docker 部署，部署中，可用后再以此页为准）
  • 设计文档：docs/DESIGN.md　开发记录：docs/QODER_DEV_LOG.md　验收记录：samples/VERIFY.md
  • 配置 LLM（可选）：LLM_BASE_URL / LLM_API_KEY / LLM_MODEL，三个变量缺任何一个都走抽取式答案，功能不缺。
